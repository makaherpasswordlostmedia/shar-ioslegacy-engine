## 1 · Устройство и запуск

Код — в рабочей копии (worktree или main), данные и результаты — в основной папке проекта (`common.DATA`, по git common dir):
состояния оригинала `build/ps2ref/`, сборка порта `build/`, итог близнецов `build/twins/` (в git не входит).

| файл | что |
|---|---|
| `conductor.py` | дирижёр: `run`, `gate` (Б1), `calib` (балласт памяти), `queue` (очередь вопросов) |
| `judge.py` | судья по правилам (поза, высота, курс, скорость, пешком); поле, которого сторона не знает, — в «не сверено», не в «чисто» |
| `orig.py` | сторона «Оригинал»: рецепт `tools/ps2ref/ask.py`, свой PCSX2 скрыто, профиль `TWINS_PROFILE` (по умолчанию 1) |
| `port.py` | «Порт»: лёгкий (`port_light.c` поверх мира ботов `tools/bots/world.c`) и полный (EBOOT в своём PPSSPPHeadless) |
| `ppsspp_build.sh`, `ppsspp_headless.patch` | своя сборка PPSSPPHeadless v1.20.4 с кадром по строке `SHOT` (общий PPSSPPSDL и `tools/ppsspp_run.sh` не трогаем) |
| `points.tsv` | точки маршрута |

Команды (из рабочей копии):
```
python3 tools/twins/conductor.py run --points l1_start            # обе стороны в одной точке → build/twins/<время>/report.md
python3 tools/twins/conductor.py gate                             # гейт Б1 (PASS/FAIL одной строкой)
TWINS_BREAK=judge_pose python3 tools/twins/conductor.py gate      # отрицательный контроль: обязан быть FAIL
TWINS_BREAK=no_sync    python3 tools/twins/conductor.py gate      # отрицательный контроль: обязан быть FAIL
tools/twins/ppsspp_build.sh --check                               # свой PPSSPPHeadless на месте
```
Синхронизация Б1: порт ставится в позу машины из самого состояния оригинала. Оси: z порта = −z оригинала, курс порта h = π − курс
оригинала (нос оригинала — строка 2 матрицы рисования `0xa21870`). Кадры: оригинал 50/с (PAL), порт 60/с — одно игровое время.

## 12 · Трамплины (правка Роба 342, 05.10: «как будто ускоритель — не надо; на всех трамплинах как в оригинале»)

`tools/twins/rampjump.py` (бот: дороги → разгон по линии трамплина → кромка → полёт; vy, тангаж, снимок точки разгона),
`tools/twins/jumpref.py` (трассы → эталон `tests/jumps/ramps_ps2.tsv`), гейт `tests/jumps/twin.sh --gate` (порт той же точкой

- `[PS2]` Вертикального подброса в зонах jumpzone* нет (jumpzone16, 17, 2, 4; 50–106 км/ч): от кромки баллистика, g 16.
- `[PS2]` «Jump boost» — продольный разгон в объёме зоны (с ~2,6 м до края, колёса на земле, газ): +8–10 м/с² к тяге, скорость
  выше предела машины (до 29,9 м/с). В полёте газ ничего не даёт.
- `[PS2]` Дом с jumpzone17: 50 и 70 км/ч — удар о стену, машина встаёт; 102 км/ч — касание конька и посадка за домом (43 м);
  106 км/ч — чисто (41 м).
- `[PS2]` В полёте машина не выравнивается: тангаж +15° → −10° (jumpzone16, 70 км/ч). `[порт]` выравнивание airLevel 0,5 — до −1,5°;
  при airLevel 0,15 — до −8° (не менялось: общий параметр машины, в том числе на земле в наклоне).
- `[правило порта]` car.c `jumpZoneDrive`: JUMP_ZONE_ACC 9 м/с² × газ вдоль курса в объёме зоны, раздутом на полудлину машины,
  колёса на земле; прежнее правило 47 — `CAR_JUMP_BOOST=1`. Расхождения подвески (не зоны) — `tests/jumps/ramps_known.tsv`.
